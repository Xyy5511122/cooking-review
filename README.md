# cooking-review

一个 Unity 2D 烹饪游戏项目的**外部评审材料**仓库。不含源码、不含图片素材，只有规格、脚本产出的数字和评审记录。

## 为什么需要这个仓库

执行方（AI，能读仓库、跑命令、量像素）同时负责写规格和验收，等于自己出题自己打分。这个仓库的目的是把**判断依据**从执行方的叙述里剥离出来，交给外部评审。

核心约定：**任何结论都必须能被一段脚本推翻。**

## 三条硬规则

1. **评审方不看图。** 图只给用户，因为审美判断是用户的职责，不是模型的。
2. **数字必须可复现。** `FACTS.md` 每张表都带生成命令与输入 SHA256。
   - **N2 表 1 / 表 2 已可独立重跑**：`python tools/make_n2_facts.py verify` / `live` 只读 `N2_acceptance/evidence/` 的公开日志，执行方实测输出与 `FACTS.md` 逐字节一致。
   - **N2 表 3–9 已知例外**：输入含私有 Unity 仓库的 PNG / JSON / git，公开仓库只有脚本与哈希，评审方**不能独立重跑**；可用 `N2_PUBLIC_ONLY=1 python tools/make_n2_facts.py changes` 演示脚本拒绝边界。见 `SPEC.md §E` / `EXTERNAL_REVIEW.md` [6]。这条不因「完工」或复评 PASS 消失。
   - **复评已核对**：评审方检查了脚本的公开输入路径与 `private_ok()` 限制，确认 `verify` / `live` 可公开重跑、缺私有输入时拒绝并保护 FACTS；裁决 C 明确这是**有限**的外部复核，不等于全部复现。
3. **只找反例。** 「整体合理」不是有效输出。

## 术语

| 词 | 含义 |
|---|---|
| 切面 / cutface | 土豆被切开后露出的截面贴图，96×819 像素的竖窄条 |
| 丝束 / strip bundle | 切好后飞出的土豆丝，6 张独立 Sprite |

| 直边占比 straight | 轮廓停留在最大宽度的长度占总长比例。矩形≈1.0 |
| 束腰 waist | 中段最薄处 / 全局最厚处。1.0 = 没有束腰 |
| solidity | 轮廓面积 / 凸包面积。散乱线束低，整块形状高 |
| prep_hand | 青椒前置流程里按住椒身的手部 Sprite（1024²） |
| sheet_1..5 | 青椒摊平片被逐刀切剩的五张分段贴图，替代 `Image(Filled)` 硬裁切 |
| stages | 正式素材目录 `Assets/Resources/Art/Unified_v2/food/stages/` |
| 肤色重心 | 手部 PNG 中肤色像素的坐标均值，用来对齐抓握点（不是整层 alpha 中心） |
