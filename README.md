# cooking-review

一个 Unity 2D 烹饪游戏项目的**外部评审材料**仓库。不含源码、不含图片素材，只有规格、脚本产出的数字和评审记录。

## 为什么需要这个仓库

执行方（AI，能读仓库、跑命令、量像素）同时负责写规格和验收，等于自己出题自己打分。这个仓库的目的是把**判断依据**从执行方的叙述里剥离出来，交给外部评审。

核心约定：**任何结论都必须能被一段脚本推翻。**

## 目录

| 路径 | 内容 |
|---|---|
| `PROTOCOL.md` | 评审协议。**评审方先读这个** |
| `EXTERNAL_REVIEW.md` | 历次评审意见原文留痕（收到意见后由执行方原样写入） |
| `tools/asset_lint.py` | N1 的测量器 |
| `tools/make_n2_facts.py` | N2 的测量器：从日志 / PNG / JSON / git 生成 `FACTS.md` |
| `tools/ref_*.png` | N1 达标参照（数值达标、美术不可用）。**评审方不需要读图** |
| `N1_spec_freeze/` | 节点 1：土豆切面 A-2 / 丝束 v06 规格冻结，待评审 |
| `N2_acceptance/` | 节点 2：青椒 S7–S12 / v08 产出验收，`README / SPEC / FACTS` 三文件，待评审 |

## 节点索引

| 节点 | 时机 | 评审方要回答 | 状态 |
|---|---|---|---|
| N1 规格冻结 | 动手前 | 哪些条款无法判定 / 偏离原意 / 自相矛盾 | **待评审**（土豆线） |
| N2 产出验收 | 宣布完成时 | 数字与结论是否互相矛盾 | **待评审**（青椒线，2026-11-13 发布） |

## 三条硬规则

1. **评审方不看图。** 图只给用户，因为审美判断是用户的职责，不是模型的。
2. **数字必须可复现。** `FACTS.md` 每张表都带生成命令与输入 SHA256。
   - **N2 已知例外**：输入文件在私有 Unity 仓库，公开仓库只有脚本与哈希，评审方**不能独立重跑**；见 `N2_acceptance/README.md` 主张 C5。这条不因「完工」消失。
3. **只找反例。** 「整体合理」不是有效输出。

## 术语

| 词 | 含义 |
|---|---|
| 切面 / cutface | 土豆被切开后露出的截面贴图，96×819 像素的竖窄条 |
| 丝束 / strip bundle | 切好后飞出的土豆丝，6 张独立 Sprite |
| Profile | 数据资产 `potato.asset`，控制切丝路线的时长与变体索引 |
| 直边占比 straight | 轮廓停留在最大宽度的长度占总长比例。矩形≈1.0 |
| 束腰 waist | 中段最薄处 / 全局最厚处。1.0 = 没有束腰 |
| solidity | 轮廓面积 / 凸包面积。散乱线束低，整块形状高 |
| prep_hand | 青椒前置流程里按住椒身的手部 Sprite（1024²） |
| sheet_1..5 | 青椒摊平片被逐刀切剩的五张分段贴图，替代 `Image(Filled)` 硬裁切 |
| stages | 正式素材目录 `Assets/Resources/Art/Unified_v2/food/stages/` |
| 肤色重心 | 手部 PNG 中肤色像素的坐标均值，用来对齐抓握点（不是整层 alpha 中心） |
