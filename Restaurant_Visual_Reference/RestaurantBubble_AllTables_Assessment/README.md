## 三、事实 / 推断 / 风险 分层

### A. 已通过实际检查确认的事实

- 五桌气泡与菜品**全部烘焙在底图** `restaurant_full.jpg` 中；其余四桌的订单显示是静态图片，与随机订单不联动。
- 只有男孩桌创建了气泡覆盖片与动态图标槽；其余四桌的 `orderBubbleGo` 为 `NULL`、`dishIcons.Length == 0`、`dishIconRoots.Length == 0`。
- 男孩桌 V3 在真实画面中：气泡内为**圆形动态菜品图标**（非椭圆盘）、暖白干净、无静态盘菜残留；轮廓与尾巴自然。
- 静态菜品数量：女孩桌 2 盘、男孩桌原本 2 盘、其余三桌各 1 盘；均带盘缘、阴影与描边。
- 五桌气泡尺寸/形状分两类：男孩/女孩为双菜大椭圆，其余三桌为单菜小椭圆。
- 五桌的遮罩、耐心条均为**每桌独立参数**；图标适配表与菜品 icon 为**共享结构**。
- Console Error = 0；工作区与基线逐行一致。

### B. 根据现有结构推断的结论

- 动态图标数据结构（每桌独立字段 + 静态适配表）**天然支持逐桌独立显示**，无需重构 `DiningTable`。
- 男孩桌的接入**模式**（一张 clean 覆盖片 + 3 个图标槽 + 生命周期同开同关）可复用，但**素材不能复用**：其余四桌气泡形状、尺寸、背景、尾巴方向各异，必须逐桌独立制作覆盖片。
- 单菜桌（1/2/3）若扩展，1 菜时图标放大到 148px（`BindBubbleIcons` 中 `visibleW = n<=1 ? 148f`），需要确认小气泡是否放得下。
- 覆盖片需与各自 `Cover_i` 的显隐生命周期绑定（空桌隐藏、到达显示、离场隐藏），否则会出现静态菜品残留。

### C. 尚未验证的风险

- 各桌 clean 覆盖片的**描边保护可行性**：男孩桌 R2 曾出现距描边仅 3–5px 的冲突区；其余四桌是否同样存在不可清理区，需逐桌实测。
- **8px 描边保护约束**在小气泡上更难满足（气泡内部可用面积更小）。
- **骑手桌（2/3）遮挡**：气泡位于骑手头顶上方、耐心条邻近人物与前景，图标放大后是否遮挡人物/耐心条未实测。
- `BindBubbleIcons` 中硬编码的气泡宽度 `343f` 与图标纵向中心 `102f` 来自男孩桌；换到别桌气泡尺寸后需重新标定，否则图标会偏移或溢出。
- 双菜桌（girl）的 2 盘静态菜品相邻，清理后暖白渐变连续性的难度高于单菜桌。
- 每桌顾客状态、随机订单、送菜灰化在扩展后是否完整联动，需像男孩桌一样逐桌 Play 回归。

## 四、最终报告（六项问题）

### 1. 另外四桌是否适合采用男孩桌相同的动态气泡方案？

**适合，且收益明确**：四桌当前均为静态烘焙菜品，与随机订单不联动，是同一类问题。但"适合"不等于"可直接套用"——需按桌制作独立覆盖片并重新标定图标布局。

### 2. 是否需要分别制作四张独立覆盖素材？

**需要**。没有可共用的覆盖片：女孩桌虽同为双菜大椭圆，但气泡轮廓、尾巴位置、背景与男孩桌不同；其余三桌是更小的单菜椭圆。男孩桌的 `bubble_boy_clean.png`（343×204）无法对齐到任何其他桌。

### 3. 每桌的素材制作难度与主要风险

| 桌 | 难度 | 主要风险 |
|---|---|---|
| girl (4) | 中高 | 双盘清理、盘缘相邻区域暖白渐变连续；气泡尺寸大但描边长，保护带累计风险高 |
| uncle (1) | 中 | 单菜但气泡偏小；tail 朝下偏右，需确认 8px 保护区；背景为玻璃门/窗，插值底色需匹配 |
| riderY (2) | 中高 | 气泡在骑手头顶；图标放大后可能遮挡骑手或耐心条；背景为玻璃门 |
| riderB (3) | 中高 | 同 riderY，且气泡右侧靠近绿植，暖白背景插值与遮挡关系更复杂 |

（难度排序为相对判断，属"B. 推断"；最终以逐桌像素实测为准。）

### 4. 是否存在可以共用的素材或代码结构？

**可共用（代码与配置层）**：
- `DiningTable` 的图标槽字段、`BindBubbleIcons()`、`ApplyBubbleIconFit()`、`HideBubbleOrder()`、送菜灰化逻辑——均为实例方法，无需改数据结构。
- `s_bubbleIconFits` 菜品 alpha 边界表、`RestaurantMenu.Find(id).icon` 菜品图——全局共享。
- `BuildTable` 中"clean 覆盖片 + 图标槽 + 与 `Cover_i` 同生命周期"的接入模式。

**不可共用（素材层）**：
- 四张 clean 覆盖片必须独立制作；每桌气泡宽度/图标中心参数需独立标定。

### 5. 一次性扩展还是分批扩展？

**推荐分批扩展**。理由：每桌都涉及独立的素材制作与 Play 回归，一次性铺开会把"素材问题"和"代码问题"混在一起，难以定位；男孩桌本身就是单桌 Pilot 通过后才进入下一阶段，延续该节奏风险最低。

### 6. 建议的实施顺序与理由

1. **girl (index 4)** —— 与男孩桌同为双菜大椭圆，形态最接近，验证"大双菜气泡模板"的可复制性；成功后可沉淀通用流程。
2. **uncle (index 1)** —— 单菜堂食桌，验证"小单菜气泡 + 148px 单图标"布局，且无骑手遮挡干扰。
3. **riderB (index 3)** —— 首个外卖骑手桌，专门验证气泡与骑手人物、耐心条的遮挡关系。
4. **riderY (index 2)** —— 与 riderB 同构，复用其经验，最后完成。

理由：按"素材形态相似度 → 场景遮挡复杂度"递增排序，每一步的新增变量单一，前一步的经验可直接复用到后一步；且每桌都独立走完"素材制作 → 单桌 Pilot → 独立审阅 → 集成"的闭环，与男孩桌既有流程一致。
