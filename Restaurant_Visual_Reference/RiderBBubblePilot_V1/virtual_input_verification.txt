RiderB(index3) 虚拟鼠标交互验证 — 设备/注入方式/处理链路
本轮未使用、未控制用户实体鼠标；未调用 ServeOne()/ManualTick() 改变订单状态来冒充拖拽。

[输入设备]
- 独立 Unity InputSystem 虚拟 Mouse：`RiderBDragVirtualMouse`（device id 25，description.interfaceName 为空 = 非 RawInput 实体设备）。
- 验证前先清除所有既有虚拟 mouse（本轮 removed=0，未触碰实体 RawInput）。
- 灰化取证脚本用同构虚拟 Mouse `GrayRobustVirtualMouse`（device id 26）。

[注入方式]
- `InputSystem.AddDevice<Mouse>(name)` 创建隔离虚拟设备；
- `InputSystem.QueueStateEvent(vm, new MouseState{ position=..., buttons=... })` 注入位置与左键状态；
- buttons：未按下 0 / 按下 (ushort)1；
- 关键时序：press/release 的 wasPressedThisFrame/wasReleasedThisFrame 边沿必须在**不同真实 Editor 帧**被 PointerSystem.Update 观察到。
  首次成功的 virtual_drag.py 自然满足；复跑出现 dragging=False（边沿丢失）；稳健版 gray_capture3.py 在每次 queue 之间等待多个真实帧后稳定成功。
  这是虚拟输入的帧边沿要求，非游戏缺陷；如实记录供审阅。

[实际处理链路（真实游戏指针链，日志逐项可见）]
  QueueStateEvent → PointerSystem.Update 读取 Mouse.current.position + leftButton 边沿
  → HandleFrame → PickDraggable / BeginDrag（AFTER_PRESS: dragging=True item=dish_tomato_egg）
  → 逐帧移动，物品跟随（BEFORE_RELEASE: item_pos=(1040,452)）
  → TryDrop → DropZone.OnDrop → GameManager.TryServeBowlDish
  → 校验 kind：外卖盒(bs.takeoutDish=true) 对 Takeout 骑手，匹配
  → DiningTable.ServeOne("dish_tomato_egg") → RemoveReadyDish → TakeoutServed()
  → 半价入账 + 骑手离场 + 气泡隐藏。

        投喂前后完全一致（均白 RGBA(1,1,1,1)、气泡 True）。
  Console error = 0。
