## 2. CanvasScaler 数值对照

公式：`s = sqrt((screenW/1920) × (screenH/1080))`，可视参考尺寸 `= screen / s`。

| 分辨率 | scaleFactor（Canvas 实测） | 公式 s | 差值 | 可视参考宽 | 可视参考高 | Girl 气泡屏幕边界 | Girl 耐心条屏幕边界 |
|---|---|---|---|---|---|---|---|
| 960×600 | 0.5270463 | 0.5270463 | 0.0000000 | 1821.47 | 1138.42 | x 768.4–916.0, y 345.7–428.0；右余 44 px | x 768.4–876.5, y 309.9–341.5；右余 83.5 px |
| 1920×1200 | 1.0540930 | 1.0540930 | 0.0000000 | 1821.47 | 1138.42 | x 1536.9–1832.0, y 691.5–855.9；右余 88 px | x 1536.9–1753.0, y 619.8–683.1；右余 167 px |

两者都是 16:10，所以 `s` 相差 2 倍，但可视参考窗口完全相同。
Girl 气泡参考右缘 x=1738、耐心条参考右缘 x=1663，均小于可视参考宽 1821.47，因此不裁切。
公式预测与 Unity `RectTransform.GetWorldCorners` 实测误差 ≤0.2 px；完整数值见 `coordinate_evidence.txt`。

读数说明：本会话 `CanvasScaler.scaleFactor` 属性读回恒为 1.0，但 `Canvas.scaleFactor` 与实际几何均为上表数值；
以 `Canvas.scaleFactor` + 世界角点为权威证据，未改动该属性。

## 3. Web 目标确认

- `ProjectSettings.asset:44-47`：默认桌面 1920×1080，默认 Web 960×600。
- `Assets/**/*.cs` 中无 `BuildPipeline` / `BuildTarget.WebGL`；工程文档无 WebGL 发布计划。
- 审阅仓库 `REVIEW_SUMMARY.md:17,29`：硬性目标是 1920×1080 样板 100% 复现。
- 审阅仓库中 16:10 只作为“建议抽测一次”的备注出现，不是需求裁决。

**结论：960×600 是 Unity 默认占位配置，不能等同于产品发布目标。**
本轮验证的是“如果按 Web 默认画幅运行，核心餐厅界面是否仍可用”，结果为可用，但顶部空条与备菜页右列裁切需要在需求确认后再决定是否处理。

## 4. 证据分层

**已验证（真实运行）**
- 两个分辨率均成功设置并进入 Play Mode；`Canvas.scaleFactor` 与公式完全一致。
- 五桌、气泡、图标、耐心条、金币/垃圾桶角点在屏内；截图可见。
- Girl 与 Boy 经 `PointerSystem.HandleFrame` 命中后 `served` 位分别变为 `100` / `10`，图标变灰。
- 控制台 error 条数 0。

**数学推断（与运行读数互洽）**
- 16:10 下可视参考宽 1821.47、高 1138.42；Girl 气泡与耐心条右缘留有 44–167 px 屏幕余量。
- 顶部空条高度 = screenH − 1080×s = 600 − 569.21 = 30.8 px（取整 31 px）；2 倍分辨率即 61.6 px（62 px）。

**未验证事项**
- 真实 OS 级鼠标拖拽：GameView 输入读数在 0 与有效值间跳变，闭环标定失败。未断言 OS 鼠标在 16:10 下可用或不可用。
- 未做 WebGL Player Build；结论仅覆盖 Unity Editor Game View + Screen Space Overlay。
- 未测试 4:3、21:9、竖屏等其他画幅。
