二、验证 A：真实 OS 鼠标拖拽 —— 未通过（环境输入注入失败）
------------------------------------------------------------
目标：真实 OS 鼠标从备菜槽 (game 330,203) 拖到 Uncle (game 640,600)。

坐标探针（Unity 运行时 RectTransform 世界角点）：
  bowl 中心 = (330.00, 203.00)
  Uncle 顾客中心 = (640.00, 600.00)

鼠标标定过程（move_to_game，真实 mouse_event + OS 光标 + Unity Mouse.position 闭环）：

  尝试 0..2：target=(330,203) read=(870.0,92.2)    err=(-540, +110.8)   -- 无响应
  尝试 3..6：target=(330,203) read=(351.6,625.6)   err=(-21.6, -422.6)  -- 跳变到另一固定值
  尝试 7..9：target=(330,203) read=(870.0,92.2)    err=(-540, +110.8)   -- 跳回
  CALIB_BOWL_OK = False

点击测试：
  left_down 后 PointerSystem.IsDragging = False; CurrentDrag = null
  （鼠标按下未被游戏识别，未形成拖拽）
  left_up 后 IsDragging = False

诊断（确认是环境层输入注入失败，非游戏逻辑问题）：
  - GameView.maximized = False（已排除上轮最大化导致映射失效的因素）
  - EditorWindow.focusedWindow = GameView；前台窗口句柄 = 0x10b8e（Unity 主窗口）
  - InputSystem 设备：Mouse id=2，interface=RawInput，updateMode=ProcessEventsInDynamicUpdate
  - OS SetCursorPos 能稳定把物理光标放到目标点，但 Unity Mouse.position 读数冻结在两个
    固定值（870.03,92.23）与（1220.19,201.62）之间跳变，Mouse.delta.ReadValue() 恒为 (0,0)
  - 相对 mouse_event 的斜率测量自相矛盾（sx≈0、sy≈5 且方向不符），
    请求的光标增量被系统“抵消/吸附”回原位（os 从 (631,320) 请求 +60 后读回 629,383）
  - 重启 Play Mode 后复测：读数在 (0,0) 与偶发值间跳变，仍不可靠

结论：OS 鼠标事件无法在本环境可靠驱动 Unity InputSystem。
      按任务约束，未用模拟接口替代；拖拽投喂、按下/拖动/松开的识别、Uncle 灰化、
      Boy/Girl 不受影响 —— 均记为【未验证】，不得宣称通过。
