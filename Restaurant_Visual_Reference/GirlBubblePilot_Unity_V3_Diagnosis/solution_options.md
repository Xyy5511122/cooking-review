5:4 裁切问题 —— 候选修复方案（仅提案，本轮不实施）
========================================================
前提判断：项目唯一硬性目标是"100% 复现 1920×1080 样板图"（见 REVIEW_SUMMARY.md:29），
5:4 从未被定义为目标画幅，只是二阶段偶然测试的比例。因此"是否需要支持 5:4"
应先由需求方裁决。以下方案仅在"确认需要支持 5:4"时才有意义，按风险从低到高排列。
本轮不选择、不实施任何方案。

共同约束：任何方案都不能改变 1920×1080 下五桌现有布局（用户硬性裁决），
不得为单个气泡缩放素材，不得破坏 Boy V3 / Girl V2 已审阅实现。

--------------------------------------------------------
方案 A：维持现状，明确定义"支持画幅 = 16:9 家族"
--------------------------------------------------------
修改范围：无工程改动；仅在交付文档中明确"目标画幅 16:9（含 1920×1080 / 1844×1037 等），
          5:4 不在支持范围"，并对 5:4 裁切标注为"已知非目标行为"。
对 16:9 影响：无。
五桌一致性：无影响。
是否改 CanvasScaler：否。
是否逐桌适配：否。
风险与成本：最低。代价是 5:4 显示器上右侧内容仍被裁。
适用：若需求方确认游戏只在 16:9 环境运行（PC 全屏几乎都是 16:9/16:10），这是推荐选项。
备注：16:10（如 960×600 Web 默认）需抽测一次确认，因 w/1920 与 h/1080 不完全相等，
      理论上可视参考宽略有出入，但偏差远小于 5:4。

--------------------------------------------------------
方案 B：改用 CanvasScaler 的 Match=宽度（match=0），或 Exp 匹配宽度
--------------------------------------------------------
修改范围：GameBootstrap.cs:25 一行，matchWidthOrHeight 由 0.5 改为 0（按宽度匹配）。
原理：按宽度匹配时 scaleFactor=screenW/1920，可视参考宽恒为 1920 → 横向不再裁切。
对 16:9 影响：16:9 下 w/1920=h/1080，match 取何值结果相同 → 16:9 布局零变化。
五桌一致性：五桌统一受益，无需逐桌参数。
是否改 CanvasScaler：是（仅一行的 match 值）。
是否逐桌适配：否。
风险与成本：中低。代价：5:4 下纵向可视参考高 = 1024/0.6667 = 1536 > 1080，
            画面顶部/底部会出现更多留白（比现状更明显）；UI 在 5:4 下整体变小（0.6667 倍）。
            需视觉确认留白是否可接受。改动极小、可回退。
备注：这是"整体布局策略"的最小改法，优先于任何逐桌/逐气泡修补。

--------------------------------------------------------
方案 C：为窄画幅增加统一的"安全区缩放 + 居中"适配层
--------------------------------------------------------
修改范围：新增一个画布适配组件（或在 GameBootstrap 内加逻辑），根据 screenW/screenH
          计算一个 min 缩放并给 RestaurantPanel 加统一偏移/缩放；所有桌子节点相对该面板，
          无需逐桌写死参数。
原理：以"整张 1920×1080 参考画面完整可见"为目标，取 scale=min(sw/1920, sh/1080)
      （即 match 退化为按较短边匹配），把整幅画面等比缩放后居中，窄画幅用背景/黑边填充。
对 16:9 影响：16:9 下 scale 由较短边决定且两比相等 → 布局不变。
五桌一致性：统一在一处处理，五桌都跟着同一个面板缩放，一致性好。
是否改 CanvasScaler：可能配合调整（或保留 match=0 由适配层接管）。
是否逐桌适配：否（这正是优于"逐桌写参数"的地方）。
风险与成本：中到高。需要：① 编写适配脚本 ② 确认拖拽热区 PointerSystem 用屏幕像素命中，
            缩放后热区命中是否仍对齐（需实测）③ 5:4 下投喂交互重测 ④ 多分辨率回归。
            这是最接近"整体布局策略"的正解，但验证成本最高。

--------------------------------------------------------
被否决的做法（说明理由，避免误选）
--------------------------------------------------------
X1 只把 Girl 气泡素材缩小/左移来塞进 5:4：
   违反"不得为单个气泡改素材/坐标"；且耐心条(1663)、金币(1630)、人物(1640)、
   垃圾桶(1560) 同样在右侧，仅修气泡会留下其余元素错位/仍被裁，破坏 1920 样板复现。
X2 把 CanvasScaler 改成 ConstantPixelSize 并手动缩放根节点：
   等同重写整套布局换算，牵动厨房、菜谱等所有画面，风险远超本案范围。
X3 整体模糊或加大填充掩盖裁切：
   裁切是几何越界不是画质问题，无效。

--------------------------------------------------------
决策建议（供需求方裁决，本轮不执行）
--------------------------------------------------------
1. 先由需求方回答："5:4 是否需要支持？"——目前所有证据表明项目目标只有 16:9。
2. 若不需要：选 A，零改动，把 5:4 标注为非目标。
3. 若需要且可接受顶部留白：选 B，一行改动，16:9 零影响，验证成本最低。
4. 若需要且要求"整幅画面完整可见、无裁切"：选 C，作为整体适配层一次性解决，
   并连带解决未来任何非 16:9 画幅，但要预留交互回归测试。
5. 无论选哪个，都不要在 5:4 下单独改 Girl 桌坐标或缩放 Girl 素材。
