Girl V2 —— 5:4 (1280x1024) 裁切问题：坐标与换算证据
========================================================
本文件记录"超出约102px"的坐标系归属、缩放换算复核、五桌越界清单。
所有数值来自静态代码常量 + CanvasScaler 公开公式复核，并与上一轮
GirlBubblePilot_Unity_V2 的 Unity 运行时实测读数交叉验证。本轮为只读诊断，

一、CanvasScaler 配置（来源：GameBootstrap.cs:21-25，只读读取）
--------------------------------------------------------
uiScaleMode        = CanvasScaler.ScaleMode.ScaleWithScreenSize
referenceResolution= Vector2(1920, 1080)
screenMatchMode    = CanvasScaler.ScreenMatchMode.MatchWidthOrHeight
matchWidthOrHeight = 0.5f
Canvas.renderMode  = RenderMode.ScreenSpaceOverlay
Canvas 根节点      = anchorMin(0,0) / anchorMax(1,1) / offset 全 0（铺满屏幕）

二、scaleFactor 复核（CanvasScaler 源码公开公式）
--------------------------------------------------------
MatchWidthOrHeight 使用几何插值：
    scaleFactor = exp( (1-match)*ln(screenW/refW) + match*ln(screenH/refH) )
match=0.5 时等价于 scaleFactor = sqrt( (screenW/1920) x (screenH/1080) )

  分辨率          宽比(w/1920)  高比(h/1080)  scaleFactor   可视参考宽=screenW/scaleFactor
  1920x1080 16:9   1.0000        1.0000        1.000000      1920.0   ← 可视参考宽=参考宽，无裁切
  1844x1037 16:9   0.9604        0.9602        0.960301      1920.2   ← 同上
  796x448   16:9   0.4146        0.4148        0.414699      1919.5   ← 同上
  1280x1024 5:4    0.6667        0.9481        0.795046      1610.0   ← 可视参考宽仅 1610，右侧被裁

  复核：本轮计算 scaleFactor=0.7950464
        上一轮 Unity 运行时读数 scaleFactor=0.7950464  → 差 0.0000000（完全一致）

三、"超出约102px"的坐标系归属（核心问题）
--------------------------------------------------------
Girl 气泡参考坐标（来源：UIBuilder.cs:1375-1379，左下原点）：
  x = 1458 .. 1738（宽 280），y = 656 .. 812（高 156）
  气泡右缘参考 x = 1458 + 280 = 1738

三种坐标系下的换算：
  [A] 参考坐标（UI 布局单位）：气泡右缘 = 1738
      可视参考窗口右界 = screenW / scaleFactor = 1280 / 0.7950464 = 1610.0
      以参考单位计，超出 = 1738 - 1610 = 128 参考单位

  [B] 屏幕物理像素（Screen Space Overlay 下 = 世界坐标）：
      气泡右缘屏幕像素 = 1738 x 0.7950464 = 1381.8 px
      屏幕宽 = 1280 px
      超出 = 1381.8 - 1280 = 101.8 px ≈ 报告中的"约 102px"

  [C] Canvas 局部坐标 / 锚点坐标：
      Canvas 根节点铺满屏幕，锚点(0,0)-(1,1)，UI 元素用 OffsetMin/OffsetMax 以
      参考单位定位（UIFactory.SetRect + RectInfo.worldXY）。局部坐标即参考坐标，
      与 [A] 等价，无独立换算。

  结论：报告中的"约102px"是【屏幕物理像素】（= Screen Space Overlay 的世界坐标）。
        等价表述为【128 个参考坐标单位】。二者通过 scaleFactor=0.7950464 相互换算：
        128 参考单位 x 0.7950464 = 101.8 px。
        缩放换算本身完全正确，不存在"换算错误导致多算 102px"。

  与上一轮实测交叉验证：
    上一轮 Unity 读数：Girl 气泡世界角点 x = 1159 .. 1382，屏幕宽 1280
    本轮计算：          气泡屏幕 x = 1458x0.795=1159.2 .. 1738x0.795=1381.8
    左缘差 0.2px，右缘差 0.2px → 坐标系判断成立。

--------------------------------------------------------
四、为什么 16:9 正常、5:4 裁切（同一公式的自洽解释）
--------------------------------------------------------
16:9 时 w/1920 与 h/1080 相等（如 1920/1920=1080/1080=1），
scaleFactor 同时满足宽高，可视参考宽恰为 1920 → 所有 0..1920 的 UI 全部可见。

5:4 时宽比 0.6667 < 高比 0.9481，match=0.5 取几何折中 scaleFactor=0.795：
  - 按宽度本应缩到 0.6667，但被折中放大到 0.795 → 横向"放大"了 0.795/0.6667=1.193 倍
  - 导致可视参考宽从 1920 缩到 1610，右侧 1920-1610=310 参考单位被推出屏幕
  - 同时纵向被"缩小"（0.795 < 0.9481）→ 画面上下出现留白（截图中顶部黑边）
这就是"右侧裁切 + 顶部黑边"两个症状同时出现的统一原因。

--------------------------------------------------------
六、气泡与耐心条是否同一原因
--------------------------------------------------------
是。二者都是同一 RestaurantPanel 下的固定参考坐标 UI 元素（左下原点、锚点 0），
共享同一 CanvasScaler 缩放。5:4 下可视参考宽被压到 1610，Girl 气泡右缘 1738、
耐心条右缘 1663 都超过 1610，因此同时被裁。不存在两套独立成因。
