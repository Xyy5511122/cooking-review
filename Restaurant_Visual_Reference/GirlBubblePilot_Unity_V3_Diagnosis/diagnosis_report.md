## 1. 已验证事实（可直接读源码/截图复核）

### 1.1 工程配置（GameBootstrap.cs:15-31，只读读取）
- 画布 `Screen Space Overlay`，根节点锚点 (0,0)-(1,1) 铺满屏幕。
- `CanvasScaler.uiScaleMode = ScaleWithScreenSize`，`referenceResolution = (1920,1080)`，
  `screenMatchMode = MatchWidthOrHeight`，`matchWidthOrHeight = 0.5`。
- ProjectSettings：默认屏 1920×1080，Web 960×600；**无 5:4 配置**。

### 1.2 UI 布局方式（UIBuilder.cs）
- 全工程 UI 采用**固定参考坐标 + 左下角锚点**：`Panel/ArtImage` 均用
  `UIFactory.SetRect(rt, (0,0),(0,0), off, off+size)`，注释明确"布局坐标基于 1920×1080，左下角原点"（第 7 行）。
- 五桌坐标写死在 `GuestPos/BarPos/DishPos/CoinPos/TrashPos`（1156-1189 行）；
  Girl 气泡写死 `x=1458,y=656,w=280,h=156`（1375-1379 行）；Girl 耐心条 `barX=1458,barW=205`（1416-1419 行）。
- 顶栏最右按钮（菜谱）参考 x=1230..1330（113 行）。

### 1.3 scaleFactor 独立复核（CanvasScaler 公开公式）
`match=0.5` 时几何插值：`scaleFactor = sqrt( (screenW/1920) × (screenH/1080) )`

| 分辨率 | 宽比 | 高比 | scaleFactor | 可视参考宽 = screenW/scaleFactor |
|---|---|---|---|---|
| 1920×1080 | 1.0000 | 1.0000 | 1.000000 | 1920.0 |
| 1844×1037 | 0.9604 | 0.9602 | 0.960301 | 1920.2 |
| 796×448 | 0.4146 | 0.4148 | 0.414699 | 1919.5 |
| **1280×1024** | 0.6667 | 0.9481 | **0.795046** | **1610.0** |

- 本轮计算的 `0.7950464` 与上一轮 Unity 运行时实测读数 `0.7950464` **完全一致（差 0.0000000）**。
- 16:9 家族的可视参考宽恒为 ≈1920 → 全部 UI 可见；5:4 仅 1610 → 右侧被裁。

### 1.4 "102px"坐标系归属（核心）
- Girl 气泡右缘参考 x = 1458+280 = 1738。
- 屏幕像素 = 参考坐标 × scaleFactor（左下原点、锚点 0）。
- 右缘屏幕像素 = 1738 × 0.7950464 = **1381.8 px**；屏幕宽 1280 px；
  超出 = 1381.8 − 1280 = **101.8 px ≈ 报告的 102px**。
- 等价参考单位 = 1738 − 1610 = **128 单位**（128 × 0.7950464 = 101.8 px，互洽）。
- 与上一轮 Unity 实测角点 `x=1159..1382` 对比：本轮算 `1159.2..1381.8`，误差 ≤0.2px。
- 三种坐标系：① 参考坐标（UI 单位，总 1920）；② 可视参考窗口（总 1610）；
  ③ 屏幕物理像素（总 1280，= 世界坐标）。见 `resolution_comparison/coordinate_frames_5x4.png`。

### 1.5 视觉佐证（resolution_comparison/ 真实 Play 截图）
- 1920×1080、1844×1037：五桌气泡、图标、耐心条、人物完整，无裁切。
- 1280×1024：Girl 气泡右半、耐心条、金币、人物右缘被画面右缘裁掉；**画面顶部出现黑边**（纵向未铺满）。

## 2. 原因判断（基于上述事实的推理）

1. **根因**：CanvasScaler 用 `match=0.5` 在宽高比偏离 16:9 时取折中缩放。5:4 下宽比(0.6667)与高比(0.9481)差距大，
   折中 scaleFactor=0.795 相对"按宽度"被放大 1.193 倍，使可视参考宽从 1920 缩到 1610。
   由于 UI 全部以固定坐标贴左下角，右侧超出 1610 的部分被推出屏幕。
2. **两个症状同源**：右侧裁切（横向可视变窄）+ 顶部黑边（纵向被缩小到 0.795 < 0.9481）是同一缩放决策的两面。
3. **气泡与耐心条同一原因**：同为 RestaurantPanel 下固定参考坐标元素，共享缩放，
   右缘 1738 / 1663 均 > 1610，因此同时被裁，不存在独立成因。
4. **为何 16:9 从不裁**：16:9 下 w/1920 = h/1080，三条坐标系等比对齐，可视参考宽恰为 1920。
5. **为何恰好只有 Girl 越界**：Girl 桌坐标（气泡 1738 / 耐心条 1663 / 人物 1640 / 金币 1630 / 垃圾桶 1560）
   是全表最靠右的一组；T3 RiderB 最大仅到 1361，距可视界 1610 还有 249 单位余量。
   **这是坐标分布的结果，不是 Girl 有缺陷或被特殊对待。**

范围判定：
- **局部表现**：5:4 下仅 Girl 桌（index4）被裁；其余四桌、顶栏、背景均未越界。
- **系统成因**：全局固定坐标 + match=0.5 的画幅适配策略。若只修 Girl，其他右侧元素在更窄画幅
  （如 4:3）或未来新增靠右 UI 仍会重蹈覆辙；因此应优先按"整体布局策略"处理，而非逐桌打补丁。

## 4. 建议方案（提案，不实施）

项目当前**不需要任何修复**——因为 5:4 非目标画幅，16:9 下无问题。若需求方确认要支持 5:4：

- **方案 B（推荐先行）**：`GameBootstrap.cs:25` 的 `matchWidthOrHeight` 由 0.5 改为 0（按宽度匹配）。
  16:9 下零变化，5:4 下横向不再裁切；代价是纵向留白增多、UI 变小。一行改动、可回退。
- **方案 C（整体正解）**：新增统一"等比缩放 + 居中"适配层，保证整幅 1920×1080 在任意画幅完整可见，
  五桌统一处理；需连带回归拖拽热区命中。成本最高但一劳永逸。
- **方案 A（保守）**：不改工程，文档明确"仅支持 16:9"，把 5:4 标为非目标。

被否决：只缩小/左移 Girl 气泡素材或坐标（治标且破坏样板复现、留下其他右侧元素错位）、
改 ConstantPixelSize 重写布局、用模糊掩盖裁切。详见 `solution_options.md`。

**决策前置问题**：请需求方先裁决"5:4 是否属于目标画幅"。当前全部证据表明项目目标只有 16:9。
