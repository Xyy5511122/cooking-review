# Restaurant Bubble Pilot — 第二阶段 A（静态素材视觉验证）

本目录只用于 **独立视觉审阅**。本轮尚未进入 Unity 接入阶段：未修改任何 C#、场景、`.meta`、`Resources` 或正式 `Assets` 目录，也未改变既有餐厅图。所有文件均为本轮新增。

## 1. 试验目的

验证在 `restaurant_full.jpg`（1920×1080）已画死的顾客订单气泡中，是否可以：

1. 精确裁出单个气泡并清除其中烘焙好的菜品；
2. 在不破坏气泡底色、描边、尾巴和背景的前提下，把游戏真实菜品图重新合成进去；
3. 在气泡内分别验证“两菜”和“三菜”的可读性、间距和尺寸容量。

试验桌选择 **index 0 男孩桌**。该气泡内区在五桌中最大，实测约 320×176 px，是唯一可稳定容纳三菜方案的候选。

## 4. 本轮制作方法与像素修改范围

1. 从 `restaurant_full.jpg` 裁出 `(114,206)–(457,410)`，得到 `01_bubble_original_crop.png`。
2. 用两图差分思路定位气泡内烘焙菜品：阈值 `|ΔR|+|ΔG|+|ΔB| > 60`，配合近白判定 `R≥220, G≥213, B≥200` 且 `max−min≤60`，洪泛选取菜品区域并做半径 3 像素膨胀。
3. 在气泡内两处菜盘椭圆（局部坐标约 `(102,89)–(180,141)`、`(244,82)–(324,134)`；对应整图绝对坐标约 `(216,295)–(294,347)`、`(358,288)–(438,340)`）内，用近白底色清除原菜品，保留椭圆描边和气泡背景，得到 `02_bubble_clean.png`。
4. 将游戏四道成品菜图按可用区等比缩放、加 8→26 px 羽化后合成进无菜品气泡，生成 3 个两菜预览和 3 个三菜预览。
5. 清除菜品的精确像素差异：**46,589 px**。差异包围盒（局部坐标）`(0,5)–(343,167)`，对应整图绝对坐标 `(114,211)–(457,373)`。包围盒外改动像素数：**0**。
6. 三菜预览中，三盘均完整可见、互不遮挡；但单盘可见宽度降到约 76–92 px，观感比两菜方案轻，需审阅确认是否接受。

## 5. 审阅边界

- 本轮仅做静态图片可行性验证，**没有接入 Unity**，没有改 `UIBuilder.cs` / `DiningTable.cs` / `GameManager.cs`，也没有新增或替换任何游戏内素材。
- 没有建立“订单 dishId → 气泡图标”的运行时映射，也没有验证上菜后图标变灰。
- 请独立判断：三菜可读性、两菜/三菜是否应采用不同图标尺寸、气泡背景清除是否干净、边缘是否残留原菜品痕迹。通过后再决定是否进入单桌 Unity Pilot。
