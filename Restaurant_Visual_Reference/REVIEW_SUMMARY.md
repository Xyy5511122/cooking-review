## 1. 项目背景

- 引擎：Unity 2022 + C# + uGUI，画面基准 **1920×1080**。
- 脚本目录：`Assets/Scripts/CookingDemo/`
  - `UIBuilder.cs` —— 搭建餐厅界面、坐标与美术资源绑定
  - `DiningTable.cs` —— 单张餐桌的状态机（到店 / 等待 / 用餐 / 收钱擦桌 / 离场）
  - `GameManager.cs` —— 全局状态、顾客生成、`StartBusiness()`
  - `CookingConfig.cs` —— 菜品 / 价格 / 耐心时长配置
  - `PointerSystem.cs` —— 拖拽投喂、点击收钱、长按擦桌的热区命中
- 美术目录：`Assets/Resources/Art/Restaurant/`
- 菜单：番茄炒蛋 18 / 青椒炒肉 28 / 土豆饼 16 / 酸辣土豆丝 16，每道菜耐心 **1 分钟**。

## 2. 用户的硬性裁决（反复强调，不可妥协）

1. **满员画面必须 100% 复现**用户给的那张 1920×1080 样板图：5 位顾客（左男、里侧大叔、黄骑手、蓝骑手、右女孩）、黄圆脸 + 绿黄红彩条耐心条、身前白色气泡菜盘。
2. **美术资源必须用样板图里的原件**，不许自己画。自绘的绿圆脸 + 白方框被直接否掉。
3. **准备阶段 = 完全干净的空店**；营业后顾客**陆续来**，最多 5 位。
4. **不能是静态贴图**：耐心条要真的会缩短，顾客状态 / 订单 / 上菜 / 收钱要真的有反应。用户原话："元素倒是都对了，但是没有反应……顾客都当贴图放在那里了，耐心条也完全不变。"
5. 定位图里元素必须**程序化精测**，不许目测坐标（目测网格读数被证明有系统性偏差）。

## 4. 当前终版实现方案（8.27）

设计核心：**背景直接用用户成品图**（人物 / 桌凳 / 气泡 / 菜盘全是原图像素，零穿模），动态信息只做"覆盖"和"揭示"，不再自绘任何美术。

- **准备阶段**：`PrepCleanCover`（clean 空店整图盖层）盖住所有人物 / 条 / 菜盘；`GameManager.StartBusiness()` 时隐藏。
- **顾客陆续来**：每桌一张 `mask_*` 遮罩，盖住成品图里画死的人物 + 点菜气泡 + 耐心条整体；到店 = 揭开遮罩露出原图人物；走人 / 擦桌后盖回，座位恢复全干净。
- **耐心条**：把从成品图抠出的彩条 `bar_*.png` 按精测 bbox 原位叠放（像素一致、零接缝，**不用擦除块**）；再叠一个白色 `Image` 盖住胶囊内彩色填充段，从右往左推进表示耐心下降。胶囊内部本来就是白色，白条融入其中，同时盖住动态 sprite 和底图画死的填充。
- **圆脸**：用成品图画死的原脸，`faceArt / moodFace` 已置 null（不再动态换表情）。
- **菜盘**：直接用成品图里画死的白气泡盘。
- **白条公式**（`DiningTable.UpdatePatienceBar`）：
  ```
  anchoredPosition.x = barFillStart + barFillSpan * ratio
  sizeDelta.x        = barFillSpan * (1 - ratio)     // ratio = patienceLeft / patienceMax
  ```

### 踩过的技术坑（避免给出 Already-tried 的建议）

- 新 PNG 放进 Resources 默认导成 Multiple/Tight + 裁透明边，必须强制 `spriteMode:1 / spriteMeshType:0 / pivot(0.5,0.5)`。
- `UIFactory.CreatePanel` 的 Fill 子节点 `Image.color` 默认是 `clear`，设 sprite 后**必须手动设 `Color.white`**，否则整张透明。
- `UIBuilder.T(parent,text,localPos,…)` 的 localPos 相对父面板**中心**；`Panel()/PanelLocal()` 的 x/y 才是左下角。
- 白条 `RectTransform.pivot` 必须是 `(0,0)`；用 `(0,0.5)` 会让 anchoredPosition 变成中心点、整条下移半高。
- 素材裁切宽边距必须与 UI 数组同源：曾因素材宽 235px 而数组按紧边界 144px，sprite 被压扁导致白条乱飞。
- 差分抠图方案（full − clean）已证明会穿模，不要再建议。

## 5. 当前遗留 / 待实机签核问题（请 GPT 重点看这几条）

1. **圆脸表情不随耐心变化** —— 为彻底避免错位，改用了成品图画死的原脸，代价是失去"笑脸→苦脸"的动态反馈。想要动态表情需按每桌脸位置精测后叠加 `ui_face_*` 三态。
2. **点菜气泡内容是画死的，可能与真实订单不符；上菜后气泡不变灰** —— 玩家看到的"想吃菜"和实际订单可能不一致，也没有"已上菜"的视觉反馈。
3. **顾客离场立即消失，无淡出** —— 走人时遮罩瞬间盖回，观感突兀。
4. **底部出餐台提示 / 营业 Toast 会短暂出现在前景桌面** —— 属全局 UI，不在本轮改造范围。
