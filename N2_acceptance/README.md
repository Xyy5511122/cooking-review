## 1. 背景（30 秒）

一个 Unity 2D 切菜游戏。青椒不是牛肉那种「直接切丝」：它有专属前置流程（掐头、去尾、QE 剖开摊平），
再走五段切丝。用户逐轮给美术反馈，执行方按轮改素材与少量 C#，每轮跑编译 / 数据探针 /
`DevSelfTest` / 干净 Play Mode 实机截图。S12 是用户验收后又追加的一条：把抓握的左手改成右手，
最终只镜像了一张 PNG。用户宣布完工后按既定通道送外部评审，首轮判定 `CONDITIONAL`，本文件为修订版。

## 3. 执行方的结论句（首轮评审后已收紧，这些仍是可被质疑的主张）

1. 「用户审美验收完成」——S7–S12 需求关闭，v08 为当前正式版本。**不等于完整 N1→N2 流程已执行**（青椒线从未走过 N1），也不等于无遗留问题（§5）。
2. 「S12 相对其起点快照只变了 1 张 PNG」——`FACTS.md` 表 7：45 文件快照逐 SHA 差异集合仅 `stages/green_pepper_prep_hand.png`；C# 6/6、`.asset` 2/2 未变；`Assets/` 全目录 mtime 扫描中 `.cs` / `.asset` / `.meta` 写入数为 0。相对 HEAD 的 93 行 `git status` 是 S7–S11 累计遗留，**口径不同**，不用于本结论。
3. 「已执行的自动化测试通过」——编译 0 错、`FULLRECT 33/33`、`12/12`、DevSelfTest `300 PASS / 0 FAIL`、20 帧 timeScale=0.5 自动化运行记录。**`DevSelfTest` 走业务 API 绕过 `PointerSystem`，不覆盖真实玩家鼠标/键盘输入路径；无真人试玩数据。不得写成「全流程可跑」或「完整交互流程已验证」。**
4. 「v07 验收快照字节未变」——37 文件 0 变化（表 3）；素材层测量显示整椒头尾、上下两条浅内壁切口带、椒头/底片环落料均存在**未被手层遮挡的像素**（表 8）。**这些是素材层代理量，不证明 UGUI 实际渲染可见，也不证明用户视觉上可见；实机呈现由用户目视验收。**
5. 「验收不等于提交」——HEAD `d2f0145`、分支 `refactor/data-driven-food`、工作区未 commit（表 5）。

数字依据全部在 `FACTS.md`；`SPEC.md` v2 的 N2-01..N2-16 是逐条对照表。
**本轮修订只补证据、收紧措辞，没有新增测试、没有新增验收标准。**

## 7. 评审方在 N2 只回答一个问题

**数字与结论之间有没有矛盾？** 例如：某条 FAIL 但结论写「已达标」；某条 PASS 但结论写「待改进」；
或结论写了 `FACTS.md` 里根本没有数字支撑的内容。复评时请额外核对 `EXTERNAL_REVIEW.md` 的 [1]–[6] 是否闭合。

输出沿用 `PROTOCOL.md §5` 的 `VERDICT + 最多 8 条 + 最严重一条后果` 格式，
