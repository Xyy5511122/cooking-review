## 0. 为什么这里没有阈值

`PROTOCOL.md §3` 规定 N2 不允许新增标准。本节点的判定全部是**等值 / 集合相等 / 计数**，
没有形容词，也没有「好不好看」这类需要人来判的条款。若评审方认为某条该有阈值而这里没有，
按 `N2_acceptance/README.md §6` 的纪律记为**规格缺陷**，回 N1 修订并升版本号，
不在验收现场补标准。

v2 新增的 `FACTS.md` 表 7–9 是**补证据**，三表的第三列均标注「非期望值，不产生判定」；
它们不参与 N2-01..16 的 PASS/FAIL。若评审认为这仍构成补标准，按规格缺陷记，回 N1。

## E. 数字可复现性的边界（首轮 [6] 采纳，部分补救）

| 表 | 输入 | 评审方可否独立重跑 |
|---|---|---|

| 表 3–5 / 7–9 | 私有 Unity 仓库 PNG / JSON / git 与工程外暂存目录 | **不可以**；公开仓库只有脚本与输入 SHA256 |

**剩余缺口不可补救**：把私有 PNG / 工程文件公开会违反「公开仓库只放评审文本、零图片」约定。
因此**不能宣称原始测量结果已由外部独立复现**；本节点只能确认公开材料内部的逻辑一致性。
